# Leadfinder: поиск ЛПР на сайтах компаний по ICP

## Что это

Небольшой собственный инструмент. Он проходит шаги из урока курса «Сбор базы и валидация» —
ICP → поиск компаний → контакты ЛПР → валидация → экспорт — на одном источнике: сайте самой компании.

- На входе ICP: сегменты и ключевые слова, города, роли ЛПР, исключения, лимиты.
- Компании берутся из каталога участников выставки Экспоцентра, из своего списка сайтов или из поиска по API.
- На сайте просматриваются «Контакты», «Команда», «Руководство», отдел продаж, «О компании».
- Лид — это имя, должность и рабочий адрес, которые компания сама напечатала рядом. К лиду приложены страница,
  фрагмент текста и список пройденных проверок.
- На выходе CSV в порядке колонок курса (Имя, Фамилия, Должность, Email, Телефон, Компания) и отдельный CSV
  компаний, где лид не найден, с причиной.

Готовую базу контактов инструмент не заменяет. Он находит мало, зато каждую строку можно открыть и проверить;
цифры — в разделах «Холодный запуск» и «Сравнение с коммерческой базой контактов».

Состав: `leadfinder.py` (берёт общие функции из `personalize.py`), тесты `tests/test_leadfinder.py`, примеры ICP
`icp.example.json` и `icp.demo.json`.

| Шаг курса | Здесь |
| --- | --- |
| ICP: отрасль, регион, размер, должности | файл ICP: сегменты, города, `max_staff`, роли, исключения |
| Поиск компаний | источники `expocentr`, `seeds`, `search` → `companies.csv` |
| Контакты ЛПР, а не `info@` | обход сайта, привязка «имя — должность — адрес», фильтр ролей |
| Валидация | синтаксис, домен, MX, тип адреса, свежесть страницы; причины отказов в сводке |
| Просмотр и экспорт в CSV | `leads.csv` в порядке колонок курса, рядом доказательство |
| Обновление и сегментация | дата загрузки страницы в каждой строке, `--refresh`; колонки `роль`, `город`, `сегмент` |

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

# компании из каталога выставки, указанного в ICP
.venv/bin/python leadfinder.py --icp icp.example.json --limit 30
# свой список сайтов: CSV с колонкой site (company, city, segment — по желанию), берётся целиком
.venv/bin/python leadfinder.py --icp icp.example.json --seeds sites.csv --out leadfinder_out/moy_spisok
# только показать, какие компании подошли под ICP; сайты не обходятся
.venv/bin/python leadfinder.py --icp icp.example.json --discover-only
# отказ от обработки: убрать человека или компанию из результатов и из кэша
.venv/bin/python leadfinder.py --forget <адрес или домен>
# тесты: 368, без сети и без LLM, все страницы в них выдуманы
.venv/bin/python -m pytest tests/test_leadfinder.py
```

Прокси задаётся переменной `POLZA_SOCKS=127.0.0.1:1080`; без неё запросы идут напрямую. Если прокси задан и не
отвечает, запуск останавливается с сообщением `TUNNEL DOWN`; сделанное сохранено, повторный запуск продолжит.

| Ключ | Что делает |
| --- | --- |
| `--seeds CSV`, `--expocentr ID`, `--search` | откуда брать компании; `--search` работает только с `SERPER_API_KEY` |
| `--limit N`, `--pages N` | сколько компаний взять; сколько страниц на сайт (по умолчанию 8) |
| `--refresh`, `--cache-days N` | обойти сайты заново из сети; срок жизни страницы в кэше (по умолчанию 30 дней) |
| `--retry-errors N`, `--retry-wait S` | повторить в конце запуска сайты, которые не ответили |
| `--mailto none\|matched\|card\|all` | что делать с адресом, который стоит только в ссылке `mailto` (по умолчанию не лид) |
| `--llm claude` | разбор спорных блоков через Claude Code CLI; без ключа инструмент работает полностью |
| `--min-confidence N`, `--no-mx`, `--workers N`, `--delay S`, `--out DIR`, `--cache-dir DIR` | порог уверенности, без MX, потоки, пауза (не меньше 1 с), каталоги |

Результаты пишутся в каталог `--out` (по умолчанию `leadfinder_out/` рядом со скриптом):

| Файл | Что внутри |
| --- | --- |
| `leads.csv` | Имя, Фамилия, Должность, Email, Телефон, Компания, затем сайт, город, сегмент, тип адреса, источник, фрагмент, дата проверки, уверенность, проверки, отчество, роль |
| `no_lead.csv` | компании без лида: общий ящик, общий телефон, причина, сколько страниц просмотрено |
| `companies.csv` | что вернул поиск компаний и почему компания подошла; переезд сайта |
| `summary.md`, `summary.json` | сколько компаний, страниц и запросов; лиды по типу адреса и роли; отказы по причинам |
| `state.json`, `suppression.json` | состояние для продолжения запуска; список отказов (только SHA-256) |

## Правила продукта

На каждое правило есть тест.

- **Только собственный сайт компании.** Соцсети, LinkedIn, каталоги и базы контактов не используются. Из каталога
  выставки берётся лишь «кто компания и какой у неё сайт». Редирект страницы на чужой домен не выполняется.
  Переезд самой компании на домен с тем же именем принимается и записывается. На общих суффиксах (конструкторы
  сайтов, региональные зоны) «свой сайт» — это точный хост. Одно исключение из «только свой сайт» — сам
  `robots.txt`: его редиректы выполняются до файла, в том числе на другой сайт, и там запрашивается только
  этот файл.
- **Вежливый обход.** Не чаще одного запроса в секунду на сайт (отсчёт от конца предыдущего запроса), бюджет
  страниц, честный User-Agent `LeadFinderBot`. `robots.txt` соблюдается так:
  - Адрес перед проверкой приводится к виду, в котором уйдёт на сервер: без `/./` и `/../` (и их записи через
    `%2E`), без фрагмента. С правилами сверяется и запрашивается одна и та же запись; в очередь ссылок
    попадает она же.
  - Файл читается раньше первой страницы хоста. С ним сверяется запрашиваемый адрес и цель каждого редиректа
    (редиректов не больше 5 подряд); закрытый адрес не запрашивается. Страница из кэша тоже сверяется
    с действующими правилами.
  - Ответ 2xx, где есть хотя бы одна директива, — это правила. 4xx, кроме 429, и ответ 2xx без директив (пустой,
    HTML-страница вместо файла) — файла нет, ничего не закрыто. 429, 5xx, таймаут, нет ответа, редирект файла,
    который к файлу не привёл, — правила неизвестны: хост закрыт, пока файл не прочитан.
  - Действует группа, которая называет ровно `LeadFinderBot` (регистр не важен, `LeadFinderBot/1.0` — тоже
    она); группы `bot`, `finder`, `leadfinder` — чужие. Если своей группы нет, действует `User-agent: *`;
    своя группа её заменяет, а не дополняет.
  - Ответы 200, 404 и 410 на `/robots.txt` лежат в кэше сутки, прочие ответы и сбои — 6 часов.
  - Выключателя нет: ни ключа командной строки, ни параметра у загрузчика. Правила, разбор ответа и запись
    адреса — тот же код, что в `personalize.py` и в сборке базы. Границы — в разделе «Ограничения».
- **Лид — только то, что напечатано вместе.** Имя, должность и адрес стоят в одном блоке, не дальше 350 знаков
  видимого текста. Адрес, которого на странице не видно (только ссылка `mailto`), по умолчанию не лид.
- **Адреса не конструируются.** Адрес не собирается по шаблону и не склеивается из соседних слов. Исключение одно:
  зона, которую страница отделила пробелом (`name@site .ru`), приклеивается к адресу. Запись `name [at] site.ru`
  читается, только когда страница сама помечает её скобками. Совпадение адреса с ФИО служит подтверждением уже
  напечатанного адреса.
- **Ящики не прощупываются.** Никакого SMTP: проверяются синтаксис, принадлежность домена сайту и MX-запись в DNS.
- **Общие ящики — не лиды.** `info@`, `sales@`, `otdel.prodazh@` и подобные уходят в `no_lead.csv` как контакт
  компании. Лидом становится адрес трёх видов: именной (совпадает с ФИО), ящик должности ЛПР (`gd@`, `kd@`,
  `director@`) в карточке этого руководителя, номерной ящик, чей номер равен добавочному или городскому телефону
  из той же карточки (либо на сайте, где такие ящики у всех сотрудников).
- **Только рабочая почта на домене компании.** Бесплатные ящики лидами не становятся. Второй почтовый домен
  принимается, только если сайт сам показывает, что он свой. Ящик на бесплатной почте попадает в `no_lead.csv`
  как контакт компании, только когда назван по отделу или по самой компании; похожий на личный не сохраняется.
- **Личных телефонов нет.** В «Телефон» попадает только общий номер компании: городской или 8-800, напечатанный
  в шапке, подвале, в строке отдела или в блоке без имени человека. Номер из карточки человека не сохраняется.
  Мобильные номера не попадают ни в одну колонку; во фрагменте-доказательстве и в тексте, который видит LLM,
  от них остаются две последние цифры. Ящик, названный номером мобильного, не сохраняется. Если общего номера
  на сайте нет, колонка пустая.
- **Исключения ICP.** Компания отсеивается по названию, по словам на главной, по заявленному числу сотрудников
  и по домену. Домен из списка действует и после переезда сайта (то же имя в другой зоне, редирект на домен
  из списка), и как почтовый домен, который использует сайт. Так в прогон не попадают компании, которые уже
  есть в своей базе.
- **У каждого лида есть доказательство.** Адрес страницы, дословный фрагмент, тип адреса, список проверок,
  уверенность, ответ `robots.txt`. «дата_проверки» — день, когда страница была загружена, а не день запуска.
- **Отказ уважается.** `--forget` удаляет контакт из всех каталогов результатов и из кэша и запоминает его хэш;
  новые запуски его не выдадут. Опубликованный на сайте запрет на обработку персональных данных или отказ
  от коммерческих предложений снимает компанию.
- **Кода отправки нет.** Инструмент ничего не рассылает и не публикует.

## Проверка на размеченных вручную страницах

Эталон — ручная разметка: 99 строк на 90 сайтах. 88 строк помечены OK (человек, должность и адрес проверены
на живой странице), 11 — REJECT (общий ящик, адрес не напечатан, имя далеко от адреса, запрет на сайте,
устаревший сайт). Первую версию инструмента проверял независимый прогон; по его замечаниям инструмент был
исправлен и измерен заново. Замеры сделаны 03.10.2026 с пустым кэшем и настройками по умолчанию.

| Показатель | До исправлений | После |
| --- | --- | --- |
| Recall: найдено из 88 лидов OK | 72 (81,8 %), после повтора не ответивших сайтов | 77 (87,5 %), за один запуск |
| Precision | 125 из 131 (95,4 %) | неверных нет, 132 из 132; если три лида с оговоркой считать ошибкой — 129 из 132 (97,7 %) |
| Строки REJECT, выданные лидом | 3 | 0 |
| Проверка-атака на подставных страницах: правило нарушено | в 23 из 31 | в 0 из 31 |
| Тесты | 179 | 286 на момент замера, сейчас 368 |

- **Эвристики правились по промахам на этих же 90 сайтах.** Поэтому 87,5 % — оценка «на своих», на новых сайтах
  recall будет ниже. Отложенной выборки пока нет (см. «Как мерить и улучшать»).
- **Кто судил precision.** 77 лидов совпали со строками OK. Остальные 55 сверены с текстом страниц: 52 верных,
  3 с оговоркой (у одного из двух должностей взята та, что про другое юрлицо; у двух неточно записана роль).
- **Почему не найдены 11 из 88.** Страница закрыта в `robots.txt` — 3; страница вне типовых разделов — 2; адрес
  на другом домене, и сайт не показывает, что домен его, — 2; лимит три лида на компанию — 1; адрес стоит только
  в `mailto` — 1; роль вне ICP — 1; сайт не ответил — 1. Четыре из одиннадцати — цена правил, а не ошибки разбора.
- **После замеров** добавлены правила про телефоны, про исключения ICP и про ящики на бесплатной почте
  в `no_lead.csv`. Повтор по сохранённым страницам тех же прогонов (без сети) дал тот же набор из 132 лидов.
  Мобильный номер стоял в «Телефоне» у 21 лида и во фрагменте у 18; теперь таких нет, общий номер компании
  найден у 123 из 132. Проверка-атака по-прежнему 0 из 31.
- **04.10.2026 изменена работа с `robots.txt`** (код общий с `personalize.py`): метка порядка байтов в начале
  файла, кириллица и её процентная запись в правилах, `%2F` не равен `/`; адрес сверяется и запрашивается
  в одной записи, без `/../`; редиректы самого `robots.txt` выполняются; группа выбирается по точному имени
  робота; параметр `respect_robots` у загрузчика убран. Прогоны по сети после этого не повторялись: цифры этого
  и следующих разделов получены кодом от 03.10.2026. 368 тестов проходят.
- **Размеченный набор собран 03.10.2026.** В нём остался один контакт, который 04.10.2026 снят из ручной базы
  как устаревший; 77 из 88 посчитаны вместе с ним и после этого не пересчитывались.

Размеченный набор, результаты прогонов и кэш страниц в репозиторий не входят: в них контакты людей. Цифры этого
и следующих разделов из клона не воспроизвести. Воспроизводятся тесты и свежий прогон по любому ICP.

## Холодный запуск

Здесь ничего не подгонялось: список компаний инструмент видел впервые, один запуск, пустой кэш.

| Список | Компаний | Сайт ответил | Компаний с лидом | Лидов | Проверка лидов |
| --- | --- | --- | --- | --- | --- |
| Каталог «Металлообработка-2026», `icp.example.json` | 150 | 140 | 7 (5,0 %) | 14 | все фрагменты прочитаны автором, независимой разметки нет |
| Каталог «Агропродмаш-2026», `icp.demo.json` | 150 | 139 | 3 (2,2 %) | 3 | все три страницы открыты заново, контакт верен у всех трёх |
| 24 компании из коммерческой B2B-базы | 24 | 19 | 1 (5,3 %) | 1 | фрагмент прочитан автором |

- **Главное ограничение: выход 2–5 %.** На холодном списке прямой адрес ЛПР печатают две-пять компаний из ста.
  Инструмент точный, но малопродуктивный: чтобы получить сто компаний с лидом, нужно обойти две-пять тысяч.
- **Почему у остальных лида нет** (133 компании «Металлообработки»): на сайте только общие ящики — 87; ЛПР назван,
  но адреса рядом нет — 19; адресов нет совсем — 7; на страницах почти нет текста — 4; найден человек с ролью
  вне ICP — 4; `robots.txt` закрывает сайт — 3; адрес рядом с именем не его — 3; сайт уводит на чужой домен — 2;
  прочее — 4. Для таких компаний в `no_lead.csv` лежат общий ящик и причина.
- **Один из трёх лидов «Агропродмаша» оказался дублем ручной базы.** В исключениях стоял прежний домен компании,
  каталог дал новый в другой зоне. Правило исключений после этого исправлено; повтор по сохранённым страницам
  даёт два лида.
- **Цена.** 150 компаний — от 11,3 до 15,3 минуты и от 1455 до 1621 запроса: «Металлообработка» — 678 с
  и 1455 запросов, «Агропродмаш» — 917 с и 1621 запрос. Без платных API и без LLM.

## Сравнение с коммерческой базой контактов

Инструмент и готовая B2B-база контактов решают одну задачу с разных сторон, поэтому они сравнены на одних
и тех же списках компаний. Замер 03.10.2026: три списка, 369 сайтов, поданы в фильтр «сайт компании» базы.
Первые три строки таблицы — счётчики её собственного поиска; ЛПР здесь — фильтр по уровню должности,
от руководителя до основателя. Название сервиса не привожу: сравнивается способ сбора, а не продукт.

| | Наша база лидов на день замера | Каталог «Металлообработка-2026» | Каталог «Агропродмаш-2026» |
| --- | --- | --- | --- |
| Компаний в списке | 69 | 150 | 150 |
| Компания найдена в базе | 64 | 101 | 118 |
| Компаний, где назван хотя бы один ЛПР | 53 | 77 | 82 |
| Компаний, где у ЛПР есть адрес почты | 19 | 20 | 18 |
| Инструмент: компаний с лидом | список собран из лидов | 7 | 3 |

- **Охват у базы шире.** На двух нейтральных списках (300 компаний из каталогов выставок) база показывает ЛПР
  с адресом почты у 38 компаний (12,7 %), инструмент находит лид у 10 (3,3 %). Один из трёх лидов
  «Агропродмаша» — дубль ручной базы, см. «Холодный запуск».
- **Что стоит за счётчиком.** Счётчик говорит, что адрес есть, но самого адреса не показывает. Открыть удалось
  25 адресов ЛПР — на сколько хватило бесплатного тарифа. Из них 8 — рабочий ящик самого человека
  (3 напечатаны на сайте компании, 5 публично не подтверждены), 6 — ящик отдела или бухгалтерии, записанный
  на имя директора, 9 — адреса на бесплатной почте, 2 — адрес другого человека.
- **Откуда база берёт людей.** В 38 строках «ЛПР с адресом» нейтральных списков источник человека —
  государственный реестр юрлиц у 26, профессиональная сеть у 10, соцсеть у 2.
- **Слепая проверка.** 50 лидов вперемешку — 30 случайных из нашей базы и 20 из коммерческой — оценили
  проверяющие, которые не знали источника. Критерии одни: подтверждаются ли сегодня человек и должность
  и чей это адрес. ЛПР подтвердился, и адрес оказался рабочим (не личным и не чужим), у 29 из 30 наших лидов
  и у 7 из 20 лидов базы. Эти 20 строк отобраны вручную, а не случайно, и интервалы широкие: 7 из 20 — это
  от 18 до 57 % при доверии 95 %, 29 из 30 — от 83 до 99 %. Шкала требует публичного подтверждения адреса,
  а наши лиды по построению взяты со страниц, где адрес напечатан; охват и телефоны она не учитывает.
- **В обратную сторону.** На 24 компаниях, взятых из этой базы (третья строка таблицы в «Холодном запуске»),
  инструмент дал лид у 1 из 19 ответивших сайтов.

Что даёт база и чего нет у инструмента: охват, несколько человек на компанию, телефоны, первые лица
из реестра, люди из профессиональной сети там, где сайт молчит, юридические данные (ИНН, ОКВЭД, выручка,
численность). Что даёт инструмент: рабочий адрес, который компания напечатала сама, со ссылкой на страницу
и фрагментом — происхождение каждой строки можно проверить.

Оговорки. Список нашей базы смещён в нашу пользу: это компании, где лид у нас есть по построению; нейтральные
списки — два каталога. Двадцать пять открытых адресов — мало для выводов о базе в целом. Ящики не проверялись
ни у кого: о доставляемости эти цифры ничего не говорят. Источники дополняют друг друга: база даёт охват,
телефоны и первых лиц, инструмент — проверяемое происхождение адреса. Какой источник приносит больше ответов,
покажет только рассылка; план эксперимента — в следующем разделе.

### Что добавить в инструмент

Из сравнения видно, чем дополнить инструмент. Первые два пункта расширяют правило «только собственный сайт»,
поэтому источник у такой строки записывается так же явно, как страница сайта.

- **Первое лицо из ЕГРЮЛ для каждой компании.** Реестр — открытые данные, и руководитель назван в нём даже там,
  где сайт молчит. Адреса реестр не даёт: такая строка — «ЛПР назван, адреса нет», то есть запасной вариант
  письма, а не лид.
- **Блок контактов собственного сообщества компании в соцсети.** Его ведёт сама компания, как и сайт.
- **Несколько ЛПР на компанию вместо одного.** Инструмент выдаёт до трёх лидов на компанию, но в базу
  и в запуск идёт один, остальные остаются в рабочих файлах. Второй ЛПР — запасной адресат, если первый
  не ответил или сменил работу.

Чего инструмент не берёт сознательно:

- ящик бухгалтерии или отдела под именем директора: письмо прочитает не адресат;
- личные адреса на бесплатной почте;
- адреса, собранные по шаблону из имени и домена: их никто не печатал;
- старые версии сайтов: человек мог с тех пор сменить должность и адрес.

## Как мерить и улучшать

Офлайн, до отправки писем:

| Метрика | Как считается | Сейчас |
| --- | --- | --- |
| Выход | компаний с лидом на 100 ответивших сайтов холодного списка | 2–5 |
| Precision | доля лидов, где человек, должность и адрес сходятся со страницей | 129–132 из 132 на эталоне; 3 из 3 на «Агропродмаше» |
| Recall на эталоне | найдено из размеченных строк OK | 77 из 88, на «своих» сайтах |
| Точность роли | доля лидов с верной ролью из ICP | с оговоркой 2 из 132 |
| Свежесть | возраст страницы-доказательства | дата загрузки в каждой строке, кэш живёт 30 дней |
| Цена и скорость | запросов и секунд на компанию, платные сервисы | 9,7–10,8 запроса и 4,5–6,1 секунды, платных сервисов нет |
| Причины промахов | доля каждой причины в `no_lead.csv` и среди пропущенных строк эталона | списки выше |

Онлайн-эксперимент проводит агентство; инструмент ничего не отправляет.

- **Переменная — источник контакта.** A: лиды leadfinder (адрес ЛПР, напечатанный на сайте). B: контакты ЛПР
  из коммерческой базы. C: общие ящики тех же компаний (`info@`, `sales@`).
- **Всё остальное одинаково.** Сегмент, оффер, цепочка, домены отправки, окно. Компании распределяются по группам
  случайно, одна компания — в одной группе.
- **Метрики на 100 контактов.** Bounce, ответы, положительные ответы, назначенные встречи, жалобы и отписки.
  Итоговая — цена положительного ответа: данные, время на сбор, отправка.
- **Размер.** Чтобы отличить 3 % положительных ответов от 6 %, нужно около 750 контактов в группе (двусторонний
  тест, α = 0,05, мощность 80 %). При выходе 2–5 % группа A столько быстро не наберёт. Поэтому сначала читается
  bounce, а разница в ответах — как направление, с доверительным интервалом.

Цикл улучшения:

1. Отложенная выборка: новые сайты размечаются руками, и эвристики по ним не правятся. Нынешние 90 сайтов уже
   использованы для правок и остаются обучающими.
2. Каждый промах получает причину. На класс причин пишется тест на выдуманной странице, потом правка.
3. Правка проверяется повтором по сохранённым страницам, без сети: обучающая часть — при отладке, отложенная —
   один раз перед выпуском.
4. Итоги рассылки (bounce, «не тот человек», «уже не работает») возвращаются как новая разметка.
5. Отложенная выборка заменяется, когда на неё посмотрели слишком много раз.

## Ограничения

- Находит только тех ЛПР, кого компания сама напечатала на сайте вместе с адресом: 2–5 компаний из ста.
- Recall 87,5 % измерен на сайтах, по которым правились эвристики. На холодных списках recall не измерен:
  ручной разметки для них нет.
- Страницы, закрытые в `robots.txt`, не запрашиваются; сайт, чей `robots.txt` не получен, не обходится, пока файл
  не прочитан. На файл одна-две попытки; неудача запоминается на 6 часов, раньше файл спрашивают `--refresh`
  и повтор не ответивших сайтов в конце запуска. Выключателя нет ни в командной строке, ни в коде загрузчика.
- Границы работы с `robots.txt`. Группу `User-agent: LeadFinderBot` соблюдает только leadfinder: `personalize.py`
  и сборка базы подчиняются своим группам, и сайт, закрывшийся от `LeadFinderBot` по имени, они читают.
  `Crawl-delay` не учитывается, темп задаёт `--delay`. Директива с опечаткой (`Dissallow`) пропускается.
  Из файла читается не больше 3 МБ. Адрес сравнивается с правилом буквально: `//`, `%2F`, обратная косая черта —
  обычные знаки пути, и сервер, который сам их переписывает, может отдать по такому адресу закрытую страницу.
  Поведение закреплено тестами на выдуманных ответах серверов; ответ, которого среди них нет, может быть
  обработан иначе.
- Страницы вне типовых разделов обход не находит. Сайты, которые целиком рисуются скриптами, не читаются:
  браузер не запускается.
- MX подтверждает, что домен принимает почту, но не что ящик существует. Перед рассылкой список стоит прогнать
  через валидатор, как советует курс.
- «Телефон» — только общий городской номер или 8-800. У компании, которая печатает лишь мобильные, колонка пустая.
  Городской номер из карточки, где имя не распознано, может быть принят за общий.
- Исключение по имени домена в другой зоне может отсеять однофамильца компании из списка; это видно в сводке,
  в блоке «Отсеяно на этапе поиска компаний».
- Свежесть: лид отклоняется, если страница сама сообщает старую дату обновления или лента на главной давно
  остановилась. Старый год в подвале только снижает уверенность.
- Размер компании проверяется только при заданном `max_staff` и только по числу сотрудников, которое сайт заявляет сам.
- Поиск через Serper на живом ключе не проверялся, он покрыт тестом на подставном ответе API. Список участников
  выставки длиннее 3 МБ читается не до конца.
- Словари имён и должностей русские и английские; редкое имя распознаётся, только когда сразу за ним стоит должность.
- Кэш страниц хранит страницы целиком, вместе с тем, что на них напечатано. Он лежит в `.cache/` и не публикуется.
